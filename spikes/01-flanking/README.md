# スパイク #1: 日本語 flanking の Lezer 拡張 — 結果: **GO**

移行計画の go/no-go ゲート。「`日本語の**強調**` を CommonMark の flanking
規則を緩めて検出する」を Lezer(@lezer/markdown)の公開拡張 API だけで
実現できるかを検証した。

## 結果（2026-09-02 実測）

| 検証 | 結果 |
|---|---|
| 厳選 15 ケース（cases.txt） vs 参照実装オラクル | 緩和拡張で **15/15 一致**（素の CommonMark は 13/15） |
| fixtures 3 本の段落全 113 行 vs 参照実装オラクル | **113/113 一致** |

素の CommonMark が落ちる代表例: `カギ括弧**「テスト」**のように内側が句読点でも検出する`
（開き `**` の直後が句読点・直前が文字なので left-flanking にならない）。

## 実現方法（relaxed-emphasis.mjs）

1. 組み込み Emphasis パーサの**前**（`before: "Emphasis"`）に割り込む
   InlineParser を登録し、`*` の連続をすべてこちらで消費する。`_` は
   組み込み（厳密 CommonMark）に任せる — snake_case が守られる
2. 開閉判定を参照実装と同じ「開き = 直後が空白でない / 閉じ = 直前が
   空白でない」に緩めて `cx.addDelimiter()` する
3. **長さ（1/2/3）ごとに別のデリミタ型**を割り当てる。Lezer の汎用
   ペアリング（resolveMarkers）は「同じ型・直近の開き」を対にするので、
   参照実装の「完全一致長 + スタック」方式と同じ結果になる。
   Lezer 内部の強調サイズ処理（min-2 消費・rule-of-3）は非公開の
   デリミタ型と同一性判定で結び付いていて再利用できないが、**不要だった**

再現: `npm install && node check.mjs`（oracle*.json は hitofude リポジトリの
`hitofude/core/inline_scanner.py` の `scan()` 出力から生成）。

## 製品実装への持ち越し事項

- `~~`（取り消し線）と `::`（ハイライト）も参照実装では同じ緩和が入る。
  同じパターンで書ける（`::` は `defineNodes` でノード追加が必要）
- **オフセットの単位差**: JS/CM6 は UTF-16 コード単位、Python オラクルは
  コードポイント。BMP 内の日本語では一致するが、絵文字等サロゲートペアが
  入ると 1 ずれる。golden との突き合わせ時は変換を挟むこと
- 長さ 3（`***強調斜体***`）は「マーカー 3 文字の StrongEmphasis 1 ノード」で
  表した（参照実装の STRONG_EM と同型）。CM6 の慣行（Strong の中に Em）に
  寄せるなら resolve 先を分ければよい
- `**a *b** c*` のような交差ネストは参照実装（パス順マスク方式）と
  結果が異なり得る。参照実装自体が CommonMark 非準拠の独自挙動なので、
  どちらを正とするかは製品テストを書く時点で決める
