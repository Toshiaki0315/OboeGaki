# TASKS.md — 実装タスクと進捗

hitofude（参照実装）との機能差分 [docs/hitofude-gap.md](hitofude-gap.md) を
優先順に並べ直したバックログ（2026-09-03 起票）。各タスクの根拠
（参照実装のモジュール・ADR・タスク番号）は差分一覧の該当行を参照。

優先順の考え方:

1. **第 1 群** — 毎日の利用で穴になっているもの。小さく作れて効きが大きい
2. **第 2 群** — 書き味と表示の完成度。エディタとしての質を参照実装に揃える
3. **第 3 群** — ノート管理・検索・設定の充実。数が増えてから効いてくる
4. **第 4 群** — 大物・専門機能。単体で設計判断（ADR）が要るもの
5. **待ち** — 外部要因でブロック中

着手の規約: 1 タスク = 1 ブランチ、TDD（RED→GREEN→`make check`→commit）。
着手したらチェックボックスを `[-]`（作業中）にし、完了で `[x]` に変える。

## 第 5 群 — PowerPoint の見栄え（md2pptx 相当へ）

いまの書き出しは「ざっくり作って手で整える」構え（ADR-0039）。それは
残したまま、**手で整える量を減らす**。上から効く順に並べてある。

質問（2026-09-05）の調べで分かったこと: pptxgenjs は**ゼロから組む**道具で、
既存の .pptx をテンプレートとして読む口が無い（型定義に該当 API 無し）。
5-6 だけ道具立てが変わる。

- [x] **5-1. インライン装飾を落とさない**（太字・斜体・打ち消し・インライン
      コード・リンク）。いまは `slides.ts` の `plain()` が記号ごと落として
      いて、素の文字になる。**差がいちばん大きいのはここ**。
      pptxgenjs の `addText` はリッチテキストの配列を受ける
- [x] **5-2. 表とコードの見栄え**（見出し行の塗り・罫線・列幅、等幅と背景）
- [x] **5-3. スライドの体裁**（スライド番号・フッタ・セクション扉）。
      いまは 2 つ目以降の `#` が**捨てられている**ので、扉にして拾う。
      共通の体裁は `defineSlideMaster`
- [x] **5-4. 段組み / カード**（横並びの箱）。**新しい記法は作らなかった** —
      スライドの中の `###` が 2 つ以上あればそれぞれ箱になる。表・コードが
      あるときや、小見出しの前に本文があるときは今までどおり縦に流す
- [x] **5-5. 見た目の設定**（`slide-font` / `slide-mono` / `slide-accent` を
      front matter から。**ノートと一緒に運ぶ** — 設定に置くと資料ごとに
      変えられず、別の機械で開いたときに再現しない）
- [x] **5-6. テンプレート .pptx の適用**（ADR-0045 案 A）。環境設定で
      テンプレートを選ぶと、その**配色と書体**でスライドが出る。図形の色は
      テーマ参照にしたので、PowerPoint 側でテーマを替えても追従する。
      背景の飾りとロゴまで要るなら案 B（別の ADR）

## 第 6 群 — 書くときの近道（Qiita の `/` メニュー相当）

要望（2026-09-05）。Qiita のエディタは空行で `/` を打つと候補が出て、
選ぶと記法が入る。**並べるものの多くは覚書に既にある** — `:::note`・表・
脚注・コードブロックは実装済みで、足りないのは折りたたみだけ。

- [x] **6-1. `/` の候補メニュー**。補完の仕組みは `#`（タグ）と
      `[[`（ノートリンク）で既に動いているので、**行頭の `/` を見る
      候補源を足す**。挿入はスニペットでカーソルの置き場所まで決める
      （コードなら ``` の中、表なら 1 つめのセル）。
      - **空行の行頭だけで出す** — 日付 `2026/09/05`・URL・`and/or` で
        誤爆させない
      - **変換中は出さない**（T5。タグ補完と同じガード）
      - 並べるのは既にある機能への近道だけ。**AI に続きを書かせる候補は
        入れない** — アシスタントは「本文は書き換えません」と画面で
        約束している。入れるなら別扱いで、別のタスクにする
- [x] **6-2. 折りたたみ**（`:::details たたんだときの見出し` … `:::`）。
      **書くときは `:::note` の仲間**（案 A）。生の HTML は書き出しで
      無効にしてある（`html: false`）ので、`<details>` を通す道は開けない。
      ただし **Qiita から貼った `<details><summary>…` は読むときだけ受ける**
      （案 B の片道）。畳めないと、貼った本文が読めないまま残るため
      - エディタ: `note-container` を手本に行の並びで見つけて、
        開閉できる装飾にする（**木のノードは作らない**）
      - 書き出し・印刷: markdown-it の container で `<details><summary>`
      - できたら 6-1 のメニューに `details` を足す

- [x] **6-3. コードの言語の補完**。` ``` ` の直後で言語名の候補を出す
      （要望 2026-09-05。Qiita と同じ入口）。
      - **候補は「実際に色が付く言語」だけ**。色付けと同じ
        `@codemirror/language-data`（143 言語 / 名前と別名で 182 個）から
        引くので、選んだのに色が付かない、が起きない
      - 画面には `cpp` と `C++` の両方を出す（打つ綴りと読める名前）
      - **1 文字打ってから出す**。` ``` ` だけで一覧を出すと、ただの
        コードブロックを書きたいときに Enter が候補の決定に化ける
      - `python:aaa.py`（ADR-0008）は `:` より前だけを補完する
- [x] **6-4. コードブロックを濃い地にする**（要望 2026-09-05）。
      ライトのとき、Pygments friendly 系の色が薄い地に乗って読みにくい。
      **Qiita と同じで、明暗どちらでもコードだけは濃い地**にする。
      - 画面（`cm-codeblock-line`）と HTML 書き出しの両方
      - 地が濃くなるので、**字の色は github-dark 系に一本化**し、
        文字色とキャレットの色も行に持たせる（ライトのままだと
        黒いキャレットが濃い地に沈む）
      - **紙は今までどおり白地・ライトの組**（`@media print`）。
        濃い地はインクを食うし、既にそう決めてある
      - インラインの `コード` は変えない（本文の中で浮く）

- [x] **6-5. ゴミ箱をフォルダの木の中へ**（要望 2026-09-05）。左下は
      **フォルダとタグの 2 つだけ**にして、ゴミ箱はフォルダの中の 1 行に
      した。押すと**一覧が捨てたノートに変わる**（参照実装の
      `FilterKind.TRASH` と同じ組み立て。あちらでも一覧の絞り込みの
      1 つになっている）。
      - 一覧の右クリックは**「元に戻す」「完全に削除…」だけ**。ゴミ箱の
        中身にピン留めや改名を許すと、戻したときの状態が読めない
        （参照実装 note_actions と同じ判断）
      - **ゴミ箱は索引に無い**（T7 の走査対象外）ので、一覧の中身は
        `trash_list` から。並びは捨てた新しい順に固定（更新順 / 名前順の
        選びは出さない）
      - 落とし先としての振る舞い（ノートを落とすと捨てる・右クリックで
        空にする・Finder で開く）はそのまま

- [x] **6-6. 手引きに載っていない操作を書く**（調べ 2026-09-06。
      [other-editors-gap.md](other-editors-gap.md) §4）。**実装ゼロで
      機能が増える**。行の移動・行の複製・ノートの中の置換。
      複数カーソルは**動かないので書かない**（同 §4 の注）
- [x] **6-7. メニューから PDF で書き出す**。今も `Cmd+P` →「PDF として
      保存」でできるが、気づかれない。中身は印刷と同じ道でよい
- [x] **6-8. 画像の大きさ指定**。写真を貼ると本文幅いっぱいに出て縮め
      られない。記法は `![説明|300](道)`（Obsidian と同じ）。
      **ほかのビューアで開いても画像が壊れない**ほうを採る —
      `![](img =300x)` 系は URL が壊れる

## 第 7 群 — ポメラから取り入れる（調べ: [pomera-ideas.md](pomera-ideas.md)）

要望 2026-09-06。**足すのは日本語で長文を書く道具立てだけ**に絞る
（あの機械の価値は引き算なので、機能を全部持ってくるのは筋が悪い）。

- [x] **7-1. アウトラインで節ごと動かす**（ポメラの目玉）。今は飛ぶだけ。
      見出しを選んで**その節を丸ごと**上げ下げできるようにする。
      - 範囲は `headingSection`（6-2 で直したもの）をそのまま使う
      - **本文を書き換える操作**なので、`Cmd+Z` 1 回で戻ること
      - 出し方はアウトラインの右クリック（この app の作法）
- [x] **7-2. 選んだ語を辞書で引く**。ポメラは電子辞書を積んでいる。
      Mac には辞書があるので `dict://` に渡すだけ。**外へ出ないので
      確認の窓は出さない**（生成 AI に渡すのとはそこが違う）
- [x] **7-3. 原稿用紙の枚数**。日本語の書き手は 400 字詰めで測る。
      **単語数は出さない**という既存の判断（語の区切りが無い）は変えない
- [x] **7-4. 行番号の表示**。人と原稿をやり取りするとき「◯行目」で話せる。
      設定で on/off（既定は off — ふだんは要らない）
- [x] **7-5. 日付を選んでその日のノートを開く**。「今日のノート」はあるが
      **昨日・先週に戻れない**。日記に使う人に効く
