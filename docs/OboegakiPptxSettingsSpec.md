# OboeGaki 環境設定「PowerPoint」タブ 仕様 v1.0

`docs/oboegaki-pptx-export-spec.md`（出力仕様）の **L1 層＝アプリ UI 設定** を具体化したもの。
Markdown では指定できない「器」の部分を、環境設定タブから制御できるようにする。

## 0. このドキュメントの読み方

- **人間向け**: 各章の冒頭に設計判断の理由を書いている。
- **Claude Code 向け**: すべての設定項目に `CFG-xx`、UI 構造に `UI-xx` の ID を付けている。
  実装・テスト名には必ず ID を含めること。出力仕様側のルールID（`G-xx` `T-xx` 等）との
  対応も表に書いてあるので、UI を触ったときにどのルールの定数が変わるかを追える。

---

## 1. 設計原則：何を設定に置き、何を置かないか

### 1.1 判断基準

> **文書ごとに変わるものは Markdown の構造から推論する。
> 文書をまたいで一貫させたいものだけを設定に置く。**

| 置く（環境設定） | 置かない（Markdown の構造から推論） |
| --- | --- |
| 用紙の縦横比、背景色、フォント、余白 | どこでスライドを分けるか（見出し・`---`） |
| 配色パレット、フッタの有無 | どのレイアウトを使うか（C-01〜C-14） |
| 分割の粒度、情報密度の既定値 | タイトル、本文、箇条書きの中身 |
| 発表者ノートの扱い | 画像の左右（Markdown 内の出現順で決まる） |

この線引きにより、**Markdown に独自記法を足す動機が消える**。
「この設定は本当に文書ごとに変わるのか？」を追加時の判断基準にすること。

### 1.2 設定タブを増やすときの注意

設定項目を増やすほど、既定値のまま使うユーザーの体験は悪くならないが、
**既定値が悪いと全員が悪い出力を得る**。設定は逃げ道であって、既定値の代わりではない。
既定値は「何も触らずに書き出して綺麗」であることを常に維持する。

## 2. 設定のスコープ（3 層）

| ID | スコープ | 保存先 | 用途 |
| --- | --- | --- | --- |
| **SC-01** | グローバル既定 | アプリ設定ストア | 環境設定タブで編集。すべての書き出しの既定値 |
| **SC-02** | 文書ごとの上書き | 文書メタデータ（.md 本文には書かない） | 「この文書だけ 4:3」等。設定した文書のみ保持 |
| **SC-03** | 書き出し時の一時変更 | 保持しない | 書き出しダイアログでの 1 回限りの変更 |

優先順位は **SC-03 > SC-02 > SC-01**。

| ID | ルール |
| --- | --- |
| **SC-04** | SC-02 は **.md ファイルに書き込まない**。フロントマターを勝手に生やすと「Markdown を汚さない」という前提が崩れる。アプリ側のサイドカー（DB / `.oboegaki/` 等）に保存する |
| **SC-05** | 文書ごとの上書きがある場合、書き出しダイアログに「この文書は既定と異なる設定です」と表示し、ワンクリックで既定に戻せる |
| **SC-06** | ユーザーがフロントマターに `theme:` 等を書いていた場合はそれを **SC-02 と同等**に扱う（読むが、こちらから書き込むことはしない） |

## 3. 設定スキーマ

```ts
interface PptxSettings {
  version: 1;                       // CFG-90 マイグレーション用

  page: {
    preset: "16:9" | "4:3" | "16:10" | "a4-landscape" | "a4-portrait" | "9:16" | "custom";
    customWidthIn: number;          // preset === "custom" のときのみ有効
    customHeightIn: number;
    unit: "in" | "cm";              // 表示単位のみ。内部は常に in
  };

  theme: {
    presetId: string;               // "navy" | "mono" | "warm" | "custom-<uuid>"
    palette: {
      primary: string; secondary: string; accent: string;
      background: string; surface: string;
      text: string; textMuted: string; onPrimary: string;
    };
    backgroundStyle: "light" | "dark" | "sandwich";
  };

  font: {
    jp: string;                     // メトリクス同梱フォントから選択（CFG-30）
    latin: string;
    mono: string;
    fallbackJp: string[];           // 例: ["Yu Gothic", "MS PGothic"]
    scale: "small" | "normal" | "large";   // タイプランプ倍率 0.9 / 1.0 / 1.15
  };

  layout: {
    splitLevel: 1 | 2 | 3;          // 既定 2 (H2 で改ページ)
    density: "full" | "normal" | "sparse";
    maxBulletItems: number;         // 3–10、既定 6
    continuationSuffix: string;     // 既定 "（続き）"
    marginScale: "compact" | "normal" | "wide";  // 0.8 / 1.0 / 1.25
  };

  decoration: {
    imageCaption: boolean;          // 既定 false（alt を代替テキストにのみ使う）
    codeLanguageLabel: boolean;     // 既定 true
  };

  footer: {
    pageNumber: boolean;            // 既定 true
    text: string;                   // 既定 ""
    showDate: boolean;              // 既定 false
  };

  notes: {
    keepOriginalText: boolean;      // 既定 true（SH-10）。OFF は非推奨
    llmSummary: boolean;            // 既定 false（SH-18）
  };

  advanced: {
    lintLevel: "off" | "warn" | "strict";  // 既定 "warn"
    reproducible: boolean;                 // 既定 false（TS-02）
  };
}
```

## 4. タブ構成

### UI-01 タブの位置づけ

環境設定ダイアログに **「PowerPoint」タブ**を追加する。
将来 PDF や画像出力を足す可能性を考え、内部的には `出力 > PowerPoint` という
階層で持つ（表示は 1 階層のままでよい）。

### UI-02 セクション構成（上から順）

```
┌─ PowerPoint ────────────────────────┬── プレビュー ─────┐
│ 1. スライドサイズ                    │                    │
│ 2. テーマと配色                      │   [サンプルスライド]│
│ 3. フォント                          │   ◀ 1 / 4 ▶        │
│ 4. レイアウト                        │                    │
│ 5. フッタ                            │  表紙/箇条書き/    │
│ 6. 発表者ノート                      │  比較/画像+文章    │
│ ▸ 7. 詳細設定（折りたたみ）           │                    │
├─────────────────────────────────────┴────────────────────┤
│ [既定に戻す]  [テーマを書き出し] [読み込み]   [閉じる]    │
└──────────────────────────────────────────────────────────┘
```

| ID | ルール |
| --- | --- |
| **UI-03** | 変更は **即時プレビューに反映**し、保存ボタンを押させない（設定は即時保存、`[既定に戻す]` で復帰） |
| **UI-04** | `[既定に戻す]` はセクション単位でも提供する（全部戻すのは怖くて押せない） |
| **UI-05** | 詳細設定は既定で折りたたむ。通常のユーザーが触る必要がないものだけを入れる |
| **UI-06** | 各項目にはツールチップで「何に効くか」を 1 文で書く。ルールID は表示しない（ユーザー向けではない） |

**文字が溢れるかどうかを事前に判定できなくなる**。

| **CFG-31** | 欧文フォント | ドロップダウン | `Calibri` | 同上 |
| **CFG-32** | 等幅フォント | ドロップダウン | `Consolas` | 同上 |
| **CFG-33** | 任意のフォント名 | テキスト入力（詳細設定内） | — | MEAS-10 |
| **CFG-34** | 文字サイズ | ラジオ: 小 / 標準 / 大 | 標準 | T-01 |

| ID | ルール |
| --- | --- |
| **CFG-35** | ドロップダウンには **幅テーブルを同梱済みのフォントのみ**を並べる。初期同梱は `Meiryo` / `Yu Gothic` / `MS PGothic` / `Calibri` / `Arial` / `Consolas` / `Courier New` |

## 6. 用紙サイズ変更時のグリッド再計算

**16:9 前提の定数をハードコードしてはいけない。** 出力仕様 8 章の数値は
13.333 × 7.5in における導出結果であり、設定でサイズが変わったら再計算する。

```ts
// GR-01: キャンバスからグリッドを導出する（唯一の入口）
function deriveGrid(W: number, H: number, marginScale: number): Grid {
  const s = W / 13.333;                       // 幅の基準比
  const marginX = Math.max(0.5, 0.70 * s * marginScale);
  const marginTop = Math.max(0.4, 0.55 * (H / 7.5) * marginScale);
  const marginBottom = marginTop;
  const gutter = 0.20 * s;
  const columns = W >= 9 ? 12 : 6;            // GR-03
  const contentW = W - marginX * 2;
  const colW = (contentW - gutter * (columns - 1)) / columns;
  return { marginX, marginTop, marginBottom, gutter, columns, colW, contentW };
}
```

| ID | ルール |
| --- | --- |
| **GR-01** | グリッド定数は必ず `deriveGrid()` 経由で取得する。他の場所に 0.811 や 11.933 を書かない |
| **GR-02** | タイプランプは `typeScale = clamp(H / 7.5, 0.7, 1.4)` を全サイズに掛ける（CFG-38 の倍率とは別に乗算） |
| **GR-03** | 幅 9in 未満（縦向き・小型カスタム）では列数を 12 → 6 に落とす。細すぎる列はレイアウトの役に立たない |
| **GR-04** | **縦向き（H > W）では横並びレイアウトを縦積みに退避**する:<br>`COMPARISON` → 上下 2 段 / `IMAGE_TEXT` → 画像を上・文章を下 / `CARDS` 3列 → 1 列 × 3 段 / `IMAGE_FULL` → 上半分ブリード |
| **GR-05** | 用紙サイズを変更したら、その場で全スライドを再レイアウトして lint を再実行し、新たに溢れたスライド数を UI に表示する（「3 枚で文字が収まらなくなりました」） |
| **GR-06** | PptxGenJS には `pres.defineLayout({ name, width, height })` でカスタムサイズを登録し、`pres.layout = name` を **スライド追加前に**設定する。プリセット名 `LAYOUT_16x9` は 10 × 5.625in であり 13.333in ではないので使わない |

## 7. プレビュー

設定の良し悪しは数値では判断できないので、プレビューは必須と考える。
ただし変更のたびに .pptx を生成するのは重い。

| ID | ルール |
| --- | --- |
| **PV-01** | プレビューは **Frame IR から SVG を描く 2 つ目のレンダラ**として実装する。`core/` は共通なので、座標・文字サイズ・折り返しは本番と完全に一致する |
| **PV-02** | プレビュー用のサンプル文書 4 種を同梱: 表紙 / 箇条書き / 比較 / 画像＋文章。ユーザーの実文書ではなくサンプルを使う（設定画面で重い処理をしない） |
| **PV-03** | 「編集中の文書でプレビュー」ボタンを別に用意し、押したときだけ実文書の先頭 5 枚を描く |
| **PV-04** | プレビューは 200ms のデバウンスで再描画する |
| **PV-05** | プレビューはあくまで近似であることを 1 行注記する（実フォントは出力先の PowerPoint で描画されるため） |

## 8. 永続化・移行・入出力

| ID | ルール |
| --- | --- |
| **ST-01** | 設定の保存は `SettingsStore` インタフェース経由にする（`get/set/reset`）。実装は環境に応じて localStorage / ファイル / DB を差し替える。実行環境が未確定である以上ここを直書きしない |
| **ST-02** | 保存形式は `PptxSettings` の JSON そのまま。`version` を必ず含める |
| **ST-03** | 読み込み時にスキーマ検証し、**未知のキーは保持したまま無視、欠損キーは既定値で補完**する。壊れた値だけを既定に戻し、設定全体を初期化しない |
| **ST-04** | `version` が古い場合は `migrations[n]` を順に適用する。マイグレーション関数は純関数とし、テストを書く |
| **ST-05** | `[テーマを書き出し]` は `theme` + `font` + `page` を JSON で書き出す。`layout` `notes` `advanced` は個人の作業設定なので含めない |
| **ST-06** | 読み込み時、書き出し元のバージョンが新しい場合は「一部の設定は反映されません」と表示して既知のキーだけ取り込む |

## 9. バリデーションとエラー表示

| ID | ルール |
| --- | --- |
| **VA-01** | 入力は **即時検証**し、不正な値は保存しない（保存してから壊れた出力を見せない） |
| **VA-02** | エラーは項目のすぐ下に、原因と直し方をセットで出す。例:「幅は 1.0〜56.0 in の範囲で入力してください」 |
| **VA-03** | 警告（コントラスト不足・非同梱フォント）は保存を妨げない。アイコン＋実測値を出すに留める |
| **VA-04** | コントラスト計算・幅計測・グリッド導出は `core/` の関数をそのまま呼ぶ。**設定画面用に別実装を作らない**（値がずれると原因究明が不可能になる） |

## 付録 B: 今回あえて設定に入れなかったもの

| 項目 | 理由 |
| --- | --- |
| レイアウトの手動指定（このスライドは 2 カラム等） | 文書ごと・スライドごとに変わるもの。環境設定の役割ではない。必要なら書き出しプレビュー上でスライド単位に指定する UI を別途検討する |
| 箇条書きの記号（●／▪／–） | 見た目の差が小さく、項目を増やす価値が低い。テーマプリセットに含める |
| 行間・字間の数値指定 | 数値で触らせると容易に破綻する。T-03 の固定値と「文字サイズ 小/標準/大」で十分 |
| アニメーション・画面切り替え | Markdown から意図を推論できず、再編集で足す方が早い |
| スライドマスター（.potx）の適用 | 価値は高いが影響範囲が大きい。出力仕様 付録 A の通り v2 で扱う |
