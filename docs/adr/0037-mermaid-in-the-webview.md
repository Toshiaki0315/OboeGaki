# ADR-0037: Mermaid は同じ WebView で描き、書き出しには SVG を埋める

- **日付**: 2026-09-04
- **状態**: 採用
- **覆す対象**: ADR-0021 の**実現手段**（隠した QWebEngineView で
  mermaid.min.js を走らせ、`grab()` で QPixmap にする）。見せたいもの
  （フェンスを図にする・ソース無傷・キャレットでコードに戻る・
  ネットに繋がない）は全て引き継ぐ

## 背景

ADR-0021 の複雑さ——`WA_DontShowOnScreen` で show() する、`--disable-gpu`
でソフトウェア描画に固定する、透明背景が白に落ちるのでテーマ色を敷く、
3 状態のキャッシュ——は、**Qt から Chromium を借りて絵を撮る**という
構図から来ていた。Tauri 版ではアプリ自体が WebView なので、同じ JS を
その場で呼べる。落とし穴は前提ごと消えた。

残る判断は 2 つ:

1. mermaid は大きい。**図を使わない人にその読み込みを払わせない**か
2. 書き出した HTML で図をどう出すか（ADR-0007:**外部リソースを参照しない**）

## 決定

1. **動的 import にする**（`await import("mermaid")`）。図のあるノートを
   開いて初めて読み込む。ADR-0021 の「Chromium は図のあるノートを開いて
   初めて立ち上げる」と同じ考え方を、そのまま分割読み込みで実現する
2. **描画は非同期。出来るまでは生のコードを見せ、出来たところで差し替える**
   （画像 widget と同じ手口）。描いた図は（テーマ, コード）で覚える —
   装飾は打鍵やスクロールのたびに組み直されるので、同じ図を何度も
   描かせない
3. **描けない図はコードのまま。** mermaid はエラー図を返せるが、それを
   本文に置くと「直せない何か」が出る（数式 = ADR-0036 と同じ判断）。
   失敗も覚えて、同じ図を毎回試さない
4. **テーマは装飾の鍵に含める**（StateField）。DOM を読むだけにすると、
   ダークに切り替えても明るい図が残る
5. **書き出しには描いた SVG をそのまま埋める。** JS を読み込ませない
   （ADR-0007 / 画像の data URL 化と同じ約束）。描画は非同期なので
   **呼ぶ側が先に描いて渡す** — `renderHtml` は純関数のまま保つ
6. `securityLevel: "strict"`（図の中の HTML を信じない）

## 測ったこと

`npm run build` の dist/assets を before/after で比べた。

|                           | 合計       | 主バンドル  |
| ------------------------- | ---------- | ----------- |
| 数式まで（ADR-0036 時点） | 2.23MB     | 1,207KB     |
| Mermaid を足したあと      | **5.64MB** | **1,210KB** |

**主バンドルは +2KB**（こちらが書いた mermaid.ts のぶん）で、図の本体
（`mermaid.core` 683KB ＋ 図の種類ごとの遅延チャンク）は**開くまで
読み込まれない**。合計は +3.4MB 増えるが、DMG に入るだけで、起動にも
図を使わないノートにも効かない。

## 影響

- 依存が 1 つ増える（`mermaid` 11.x）。ライセンスは MIT
- ビルドの成果物が 173 チャンクになった（mermaid が図の種類ごとに
  分割している）。Tauri の同梱は `dist/` 丸ごとなので扱いは変わらない
- ADR-0021 の描画機構（mermaid_cache / QWebEngineView / grab / GPU 無効化）
  は**前提ごと不要**
- 図のあるノートを初めて開いたときだけ、読み込みのぶん最初の 1 枚が遅れる
  （そのあいだはコードが見えている）
