# ADR-0051: おぼえがきを MCP サーバとして開く（読み書き両方）

- 状態: 採用（実装は TASKS 第 10 群）
- 日付: 2026-09-11

## 背景

Claude Desktop などの MCP クライアントから保管フォルダのノートを検索・参照し、
さらに書き込めれば、ノートは「自分で読み返すもの」から「AI に読ませて使う
知識」になる（ユーザー提案 2026-09-11）。

設計上の下地はある。T3（Rust 側は WebView 非依存）により、走査・索引・検索・
タグ・リンク・履歴・ゴミ箱は `vault.rs` / `index_db.rs` / `history.rs` の
純 Rust にあり、Tauri の command はその薄い皮にすぎない。Cargo には既に
第 2 のバイナリ（`bench`）の型もある。

## 決定

### 1. 形: 第 2 のバイナリ `oboegaki-mcp`（stdio）

- `src-tauri/src/bin/mcp.rs`。同じライブラリクレートを呼ぶ。MCP の実装は
  公式の Rust SDK（`rmcp` クレート）
- 通信は **stdio**。Claude Desktop の設定にバイナリのパスと保管フォルダを
  書くだけで繋がる。ネットワークに出ない（ノートは手元から出ない）
- アプリの中に HTTP サーバを持つ案（アプリが動いているときだけ使える）は
  採らない。夜中に Claude Desktop だけ開いていても使えるべきで、アプリと
  MCP の生死を結び付けない
- `.app` に同梱し（`Contents/MacOS/oboegaki-mcp`）、環境設定に「MCP の
  設定を書き出す」を置いて、Claude Desktop 用の JSON 断片をクリップボードへ
  出す。パスを手で打たせない

### 2. 読み: 索引を読む。古ければ自分で同期する

| tool                                  | 内容                                                    | 使う既存の関数                                |
| ------------------------------------- | ------------------------------------------------------- | --------------------------------------------- |
| `search_notes`                        | 全文・`#タグ`・`after:` / `before:`（本文と同じ書き方） | `IndexDb::search`                             |
| `read_note`                           | 本文（front matter 込み）と更新時刻                     | `read_note`                                   |
| `list_notes`                          | フォルダ・タグで絞った一覧（題名・冒頭・更新時刻）      | `notes_in_folder` / `list_notes` / `tag_list` |
| `list_folders` / `list_tags`          | 木と件数                                                | `folder_counts` / `tag_list`                  |
| `related_notes`                       | 被リンク・題名の出現・共通タグ                          | `backlinks` / `related_signals`               |
| `note_history`                        | 版の一覧と本文（読むだけ）                              | `history`                                     |
| resource `oboegaki://note/<相対パス>` | ノートを資源として渡す                                  | 同上                                          |

- **アプリが動いていれば索引はアプリが育てている**（`instance-oboegaki.lock`
  で分かる。`vault_lock::acquire` と同じ判定）。MCP は読むだけ
- アプリが動いていなければ、問い合わせの前に `IndexDb::sync`（差分同期）を
  自分で走らせる。2 つのプロセスが同時に SQLite へ書かない約束はこれで守る
- 索引はキャッシュ（T7）。壊れていれば作り直してよい

### 3. 書き: `.md` だけに書く。索引は触らない

| tool                       | 内容                                                       | 使う既存の関数                                |
| -------------------------- | ---------------------------------------------------------- | --------------------------------------------- |
| `create_note`              | 題名・本文・フォルダを受けて作る（雛形も指定可）           | `Vault::create_with` / `create_from_template` |
| `append_to_note`           | 末尾に追記（見出しを指定すればその節の末尾）               | `read_note` + `save_atomic`                   |
| `replace_note`             | 本文を丸ごと差し替える（**期待する更新時刻を必須にする**） | 同上                                          |
| `daily_note`               | 今日のノートを開く・無ければ作る                           | `Vault::daily_note`                           |
| `move_note` / `trash_note` | フォルダへ移す・ゴミ箱へ                                   | `move_note` / `trash`                         |

- **書くのはファイルだけ。** アプリが動いていれば FSEvents がそれを拾い、
  外部変更の流れ（ADR-0050 の NFC 揃え、中身比較、未編集なら静かに読み直す、
  編集中なら競合の 3 択）がそのまま働く。spec §7.5 の想定どおり
- 書き込みは `autosave::save_atomic`（一時ファイル → rename）。半端な
  ファイルを監視に見せない
- `replace_note` は **楽観ロック**: 呼ぶ側が `read_note` で得た更新時刻を
  添え、違っていれば断る（AI が古い本文を元に上書きするのを防ぐ）。
  `append_to_note` はその心配が小さいので時刻なしでよい
- 履歴（`.OboeGaki/history/`）は**アプリ側の保存が残す**。MCP から書いた
  ときも、アプリが動いていれば外部変更の読み直しの次の保存で版が残る。
  動いていなければ MCP 側で `history::snapshot` を呼んで残す（版を作れる
  のは書いた本人だけ = ADR-0023 の精神）
- **消すのはゴミ箱まで。** MCP から `.trash` を空にする道は作らない

### 4. 見せない範囲

- 保管フォルダの直下に `.mcp-ignore`（1 行 1 フォルダ）があれば、その中は
  検索にも一覧にも出さず、読み書きも断る。ノートが外部の LLM に渡ることに
  なるので、渡したくない場所を持ち主が決められるようにする
- `.trash` / `templates` / 管理フォルダは既定で見せない（`vault::scan` の
  除外規則と同じ。一覧に出ないものは MCP にも出ない）

### 5. 安全側の約束

- 相対パスしか受けない。`..` と絶対パスは `existing_folder_relative` と同じ
  規則で断る（vault の外に出ない）
- 1 回の応答で返す本文の量に上限を置く（長いノートは先頭と「続きがある」
  印。クライアントのコンテキストを食い潰さない）
- ツールの説明文は日本語と英語を併記する（クライアント側の LLM が読む）

## 根拠

| 案  | 内容                                                      | 問題                                                           |
| --- | --------------------------------------------------------- | -------------------------------------------------------------- |
| A   | アプリ内に HTTP/SSE の MCP サーバ                         | アプリが動いていないと使えない。Claude Desktop は stdio が既定 |
| B   | **独立の stdio バイナリ。索引は読み、ファイルにだけ書く** | 2 プロセスの索引書き込みを避ける手当が要る（ロックで切り分け） |
| C   | Python などの別実装で `.md` を直接読む                    | 検索・関連・履歴を作り直すことになる。T3 の資産を捨てる        |

B を採る。T3 の払い戻しがいちばん大きく、外部変更の仕組み（spec §7.5）が
「もう 1 人の書き手」をそのまま受け止める。

## 影響

- Cargo に `rmcp` が増える。`.app` のサイズは実測してから判断（現状 5.4MB）
- `make check` に MCP の JSON 入出力テストが加わる（ツール層は純 Rust で
  ヘッドレスに試せる）
- 環境設定「一般」に「MCP の設定を書き出す」ボタンが増える
- docs/manual_test.md に Claude Desktop からの接続手順を置く
- hitofude-gap.md に「参照実装には無い」機能として記録する
