# ADR-0069: 段落を中央・右に寄せる（`:::center` / `:::right`）

- 状態: **検討中（実装しない）**。決めることが 4 つ残っている（末尾）
- 日付: 2026-09-28
- 関連: ADR-0035（表の列の揃え）、ADR-0067（Markdown の知識は `src/markdown/`）、
  ADR-0063（Qiita へ投稿）、`:::note` / `:::details` の囲み（B-3 / 6-2）

## 背景

「Markdown で文書の右寄せ・左寄せ・中央などの指定はできるか」という問い
（2026-09-28）。

**今できるのは表の列の揃えだけ。** 区切り行の `:` の位置（`:--` / `:-:` / `--:`）
で決まる GFM の書き方で、画面の表（ADR-0035）と HTML 書き出し（`th` / `td` に
`text-align`。2026-09-28 に手元で確かめた）に効く。Word 書き出しにも列の揃えを
渡すコードがある（`docx-blocks.ts`。出来上がりの Word では未確認）。

**段落・見出し・画像を寄せる書き方は、CommonMark にも GFM にも無い。** よそで
使われる回避策は HTML（GitHub の `<p align="center">` など）だが、おぼえがきは
生の HTML を通さない（`html: false`。例外は文字色の `<span>` と `<details>` の
決まった形だけ）。実際に `<p align="center">中央</p>` を HTML に書き出すと、
寄らずにタグがそのまま字として出た（2026-09-28）。

欲しくなる場面: 表紙や扉の題を中央に置く、日付と署名を右に寄せる（手紙・
議事録の末尾）、図や写真を中央に置く。

## 案（最小形）

今ある `:::note` / `:::details` と同じ**囲み**の形にする。書き方がおぼえがきの
中で揃い、スラッシュメニュー（`/`）にもそのまま載る。

```markdown
:::center
中央に置きたい文
:::

:::right
2026 年 9 月 28 日
野村
:::
```

- **ソースが唯一の真実（T1）。** 囲みの行は画面では隠し（`:::note` と同じ）、
  中身の行に `text-align` を当てる装飾だけで表す。文字は 1 字も変えない
- **中身はふつうの Markdown のまま。** 強調・リンク・画像がそのまま使える
  （`:::note` と同じく新しい木のノードを作らず、行の並びとして見つける）
- **見つけ方は `src/markdown/` に純関数で置く**（ADR-0067）。画面・HTML・Word・
  PowerPoint が同じ規則で読む（画面と書き出しで寄せ方が食い違わないように）
- **閉じの無い `:::center` は囲みにしない**（`:::note` と同じ。書きかけで以降の
  本文が全部中央に寄ると読めない）
- 知らない綴り（`:::centre` など）は囲みにしない — ふつうの段落として字のまま
  見せ、書き間違いに気づけるようにする（`:::note` の知らない種類と同じ考え）

### よそで開いたとき

おぼえがき以外（GitHub・Obsidian・VS Code のプレビューなど）では、`:::center` の
行が**字のまま見える**（中身は読める）。Qiita の記法にも無いはずなので、ADR-0063
（Qiita へ投稿）を進めるときは、送る前に囲みの行を外すか、先に言う必要がある
（14-0 で Qiita の記法を確かめるときに一緒に見る）。

### 却下した案

| 案                                                   | 問題                                                                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 生の HTML（`<p align="center">`・`<div style=…>`）を通す | `html: false` を開けることになる。貼り付けた本文の任意のタグが素通りする（書き出しの逃がしの前提が崩れる） |
| 行末の印（`->中央<-` など、一部の方言）              | 1 行ずつしか寄せられない。`->` は矢印として本文に普通に出てくる（誤検出）                                    |
| 属性の書き方（`{: .center}` など kramdown 流）       | おぼえがきの他の書き方と形が揃わない。行の後ろに付くので、どこまでが対象か読み取りにくい                     |
| front matter で文書全体を寄せる                      | 欲しいのは部分（題・署名・図）。文書全体の中央寄せは本文幅の設定（ADR-0018）が既に担っている                 |

## 決めること（ここが決まるまで実装しない）

1. **呼び名** — `center` / `right` の英語か、日本語（`:::中央` / `:::右`）か。
   `:::left` を置くか（入れ子が無いなら既定が左なので要らない）
2. **効かせる先** — 画面・HTML / PDF（印刷）・Word・PowerPoint のどこまでか。
   PowerPoint は枠の中の配置（`align`）と、レイアウトの決め方（第 8 群）との
   噛み合わせを見る必要がある
3. **入れ子** — `:::note` の中で `:::center` を使えるようにするか。今の囲みは
   入れ子を見ない作りで、閉じの `:::` がどちらのものかを決めていない。許すなら
   `:::note` の見つけ方も一緒に変わる
4. **中に置けるもの** — 段落だけか、見出し・画像・表も寄せるか。表は列の揃えと
   重なる（表そのものを中央に置くのか、セルの字を寄せるのか）

## 影響（実装するとき）

- T1: 装飾だけで表す（囲みの行は `Decoration.replace` で隠す。文字は変えない）
- T5: 入力補助は足さない（スラッシュメニューに雛形を足すだけ）。足すなら IME の
  手動チェックを通す
- T6: 囲みの見つけ方は `:::note` と同じ経路（行の並びの走査）に乗せる。数え直しの
  条件（`editNearBlockWidgets` の記号）に `:::` は既に入っている
- 書き出し: HTML は markdown-it-container に 2 つ足す。Word は `AlignmentType`。
  PowerPoint は決めること 2 しだい
- 手引き（同梱の「おぼえがきの使い方」）とスラッシュメニューに書き方を足す
