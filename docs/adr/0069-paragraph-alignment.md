# ADR-0069: 段落を中央・右に寄せる（`:::center` / `:::right`）

- 状態: **採用**（2026-09-28。決めること 4 つは末尾の「決定」）
- 日付: 2026-09-28
- 関連: ADR-0035（表の列の揃え）、ADR-0067（Markdown の知識は `src/markdown/`）、
  ADR-0063（Qiita へ投稿）、`:::note` / `:::details` の囲み（B-3 / 6-2）

## 背景

「Markdown で文書の右寄せ・左寄せ・中央などの指定はできるか」という問い
（2026-09-28）。

**今できるのは表の列の揃えだけ。** 区切り行の `:` の位置（`:--` / `:-:` / `--:`）
で決まる GFM の書き方で、画面の表（ADR-0035）と HTML 書き出し（`th` / `td` に
`text-align`。2026-09-28 に手元で確かめた）に効く。Word 書き出しにも列の揃えを
渡すコードがある（`docx-blocks.ts`。出来上がりの Word では未確認）。

**段落・見出し・画像を寄せる書き方は、CommonMark にも GFM にも無い。** よそで
使われる回避策は HTML（GitHub の `<p align="center">` など）だが、おぼえがきは
生の HTML を通さない（`html: false`。例外は文字色の `<span>` と `<details>` の
決まった形だけ）。実際に `<p align="center">中央</p>` を HTML に書き出すと、
寄らずにタグがそのまま字として出た（2026-09-28）。

欲しくなる場面: 表紙や扉の題を中央に置く、日付と署名を右に寄せる（手紙・
議事録の末尾）、図や写真を中央に置く。

## 案（最小形）

今ある `:::note` / `:::details` と同じ**囲み**の形にする。書き方がおぼえがきの
中で揃い、スラッシュメニュー（`/`）にもそのまま載る。

```markdown
:::center
中央に置きたい文
:::

:::right
2026 年 9 月 28 日
野村
:::
```

- **ソースが唯一の真実（T1）。** 囲みの行は画面では隠し（`:::note` と同じ）、
  中身の行に `text-align` を当てる装飾だけで表す。文字は 1 字も変えない
- **中身はふつうの Markdown のまま。** 強調・リンク・画像がそのまま使える
  （`:::note` と同じく新しい木のノードを作らず、行の並びとして見つける）
- **見つけ方は `src/markdown/` に純関数で置く**（ADR-0067）。画面・HTML・Word・
  PowerPoint が同じ規則で読む（画面と書き出しで寄せ方が食い違わないように）
- **閉じの無い `:::center` は囲みにしない**（`:::note` と同じ。書きかけで以降の
  本文が全部中央に寄ると読めない）
- 知らない綴り（`:::centre` など）は囲みにしない — ふつうの段落として字のまま
  見せ、書き間違いに気づけるようにする（`:::note` の知らない種類と同じ考え）

### よそで開いたとき

おぼえがき以外（GitHub・Obsidian・VS Code のプレビューなど）では、`:::center` の
行が**字のまま見える**（中身は読める）。Qiita の記法にも無いはずなので、ADR-0063
（Qiita へ投稿）を進めるときは、送る前に囲みの行を外すか、先に言う必要がある
（14-0 で Qiita の記法を確かめるときに一緒に見る）。

### 却下した案

| 案                                                   | 問題                                                                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 生の HTML（`<p align="center">`・`<div style=…>`）を通す | `html: false` を開けることになる。貼り付けた本文の任意のタグが素通りする（書き出しの逃がしの前提が崩れる） |
| 行末の印（`->中央<-` など、一部の方言）              | 1 行ずつしか寄せられない。`->` は矢印として本文に普通に出てくる（誤検出）                                    |
| 属性の書き方（`{: .center}` など kramdown 流）       | おぼえがきの他の書き方と形が揃わない。行の後ろに付くので、どこまでが対象か読み取りにくい                     |
| front matter で文書全体を寄せる                      | 欲しいのは部分（題・署名・図）。文書全体の中央寄せは本文幅の設定（ADR-0018）が既に担っている                 |

## 決めること（2026-09-28 に決めた。結果は次の「決定」）

1. **呼び名** — `center` / `right` の英語か、日本語（`:::中央` / `:::右`）か。
   `:::left` を置くか（入れ子が無いなら既定が左なので要らない）
2. **効かせる先** — 画面・HTML / PDF（印刷）・Word・PowerPoint のどこまでか。
   PowerPoint は枠の中の配置（`align`）と、レイアウトの決め方（第 8 群）との
   噛み合わせを見る必要がある
3. **入れ子** — `:::note` の中で `:::center` を使えるようにするか。今の囲みは
   入れ子を見ない作りで、閉じの `:::` がどちらのものかを決めていない。許すなら
   `:::note` の見つけ方も一緒に変わる
4. **中に置けるもの** — 段落だけか、見出し・画像・表も寄せるか。表は列の揃えと
   重なる（表そのものを中央に置くのか、セルの字を寄せるのか）

## 決定（2026-09-28）

検討の途中で、既存の穴が 2 つ見つかった。どちらも決定の前提に関わる。

- **PowerPoint は囲みを知らない。** スライドの解析（`lib/slides.ts`。Lezer）は
  囲みの規則を持たず、`:::note warn` の囲みは `:::note warn 注意 :::` という
  1 つの段落として字のまま出た。`:::details` も同じ（2026-09-28 に手元で確かめた）
- **画面と HTML で入れ子の読み方が違う。** HTML 書き出し（markdown-it-container）は
  外側のコロンを多くした `::::note` の中の `:::details` を入れ子として組む。画面は
  `::::note` を囲みと認識せず字のまま見せる。同じ長さの `:::` で入れ子にすると、
  HTML でも最初の `:::` で外側が閉じ、余った `:::` が字で出る

### 1. 呼び名 — `:::center` と `:::right`。`:::left` は置かない

- 既存の `:::note` / `:::details` が英語で、Qiita・Zenn の囲みも英語。書き方が揃う
- 入れ子を許さない（3）ので、囲みの中の既定は常に左。`:::left` は効かないつまみに
  なる（CLAUDE.md §6.5 の「効かないつまみを出さない」と同じ考え）
- 日本語の別名（`:::中央` / `:::右`）は受けない。同じものに綴りが 2 つできると、
  手引きもよそのツールでの見え方の説明も倍になる。`:::中央` は知らない綴りとして
  字のまま見せる

### 2. 効かせる先 — 画面・HTML / PDF（印刷）・Word・PowerPoint の全部

- HTML と Word は同じ markdown-it の解析結果から組むので、足す手間は小さい。Word は
  段落に `AlignmentType` を渡すだけで、中の画像も段落ごと寄る
- PowerPoint も段落ごとに `align` を持てる。寄せても字の折り返しと高さは変わらない
  ので、第 8 群の枠の割り方と「収まるか」の見積もり（`estimateHeightIn`）には響かない
- 一部の書き出しだけ寄らないと、書いた人がその理由を知る手段が無い。全部に効かせる
  方が説明が短い
- **前提として、スライドから囲みの行を落とす処理を先に入れる**（22-P）。上の穴の
  `:::note` / `:::details` の字漏れも一緒に直る

### 3. 入れ子 — 最初の版では許さない

- 今の `:::note` / `:::details` も入れ子を見ない作りで、それに揃える
- 別の `:::` の囲みが開いている間の `:::center` / `:::right` は囲みにせず、字のまま
  見せる（知らない綴りと同じ扱い。書き間違いに気づける）
- 入れ子が要るとわかったら、**外側のコロンを多くする規則**（`::::note` の中に
  `:::center`）を全部の囲みに同時に入れる。markdown-it-container と Zenn がこの
  規則なので、上の「画面と HTML の食い違い」もそこで消える。囲みの種類ごとに規則を
  変えると、閉じの `:::` がどれのものかが種類ごとに変わり、画面と書き出しで
  食い違いやすい

### 4. 中に置けるもの — 寄せるのは段落と見出しだけ

- 画像は段落の中にあるので段落と一緒に寄る。欲しい場面（題・署名・図）はこれで
  まかなえる
- リスト・コード・表・数式・引用は、囲みの中にあっても寄せない。コードの中央寄せは
  読めず、数式ブロックはもともと中央に置いている
- 表は寄せない。列の揃え（`:-:`）が既にあり、「表そのものを真ん中に置く」を混ぜると
  両者の違いを説明しなければならない
- PowerPoint では `##`（割る段）で枚が替わるので、囲みもそこで切れる。囲みの中に
  `##` を書いたら、そこから先は寄せない

### 実装に入るときの注意

- 見つけ方は `src/markdown/` に置く（ADR-0067）。今の `:::note` / `:::details` の
  見つけ方は `src/editor/`（note-container / details-container）にあり、HTML 書き出しが
  そこを読んでいる。`:::center` を足すときに、同じ場所へ寄せるかを 22-1 で決める
  （22-1 で寄せた。`:::` の囲みは `markdown/containers.colonContainers` の 1 本）
- 「別の囲みが開いている間は囲みにしない」（3）を守るには、`:::` の囲みの開きと閉じを
  1 本の走査で見る必要がある。今は note と details が別々に走査している
- Qiita で寄せをどう書くかは未確認。ADR-0063 の 14-0 で記法を確かめるときに、送る前に
  囲みの行を外すかを一緒に決める

## 影響（実装するとき）

- T1: 装飾だけで表す（囲みの行は `Decoration.replace` で隠す。文字は変えない）
- T5: 入力補助は足さない（スラッシュメニューに雛形を足すだけ）。足すなら IME の
  手動チェックを通す
- T6: 囲みの見つけ方は `:::note` と同じ経路（行の並びの走査）に乗せる。数え直しの
  条件（`editNearBlockWidgets` の記号）に `:::` は既に入っている
- 書き出し: HTML は markdown-it-container に 2 つ足す。Word は `AlignmentType`。
  PowerPoint は決めること 2 しだい
- 手引き（同梱の「おぼえがきの使い方」）とスラッシュメニューに書き方を足す

## 追記（2026-09-28）: 他のアプリの書き方と比べて

他のアプリの調べ（2026-09-28。利用者が持ち込んだ資料）と今の `:::center` を比べた。

| 方法 | よそで開いたとき | おぼえがきの規則との相性 | 判断 |
| --- | --- | --- | --- |
| `:::center` / `:::right`（今の形） | 字のまま見える | 画面と 4 つの書き出しで揃っている | **書く形として残す** |
| HTML（`<div align>`・`<p align>`・`<div style="text-align: …">`） | GitHub・Obsidian・Typora で寄る | 生の HTML は通さない（`html: false`）。決めた形だけを見分けるなら、貼った `<details>` と同じ扱いにできる | **読むときだけ受ける**（23-2） |
| 矢印（`-> 中央 <-`） | ほぼどこでも字のまま | `->` の誤検出。1 行ずつしか寄せられない | 採らない（上の却下のまま） |
| 画面の操作（Notion） | — | 書き方ではなく近道。今の記法の上に載る | **操作として足す**（23-1） |
| 枚ごとの指示子（Marp の `<!-- _class: … -->`） | Marp でだけ効く | PowerPoint の割り方（第 8 群）と別の仕組みになる | 採らない |
| CSS スニペット（Obsidian） | その人の手元でだけ | 書き出しに乗らない | 採らない |

### 決定 5: 選んだ行を寄せの囲みで包む・外す操作を足す（23-1）

「編集」メニューの書式の並びに「中央に寄せる」「右に寄せる」を置く。選んだ行の
前後に `:::center` / `:::right` と `:::` を差し込む。既に同じ寄せの中なら外し、
別の寄せの中なら種類を替える。`:::note` などの中では何もしない（入れ子を作らない。
決定 3）。字を変えるのはコマンドを実行したときだけで、変換中に割り込む入力補助
ではない（T5 に触れない）。

### 決定 6: 寄せの HTML を読むときだけ受ける（23-2）

GitHub の README や Obsidian・Typora のノートを持ち込むと、今はタグが字のまま
見える。決めた形だけを `:::center` / `:::right` と同じ囲みとして読む:

- 開きの行: `<div align="center">`・`<p align="center">`・
  `<div style="text-align: center;">`（`right` も同じ）。閉じの行: `</div>`・`</p>`
- 1 行の形: `<p align="center">…</p>`・`<div align="center">…</div>`（23-2 の後半）
- 扱いは `:::center` と同じ（寄るのは段落と見出しだけ・入れ子を許さない・4 つの
  書き出しでも寄せる）。開きと閉じの間はふつうの Markdown として組む
  （貼った `<details>` と同じ。CommonMark の HTML ブロックより寛い）
- **書かない。** スラッシュメニュー・手引き・23-1 の操作は `:::center` のまま。
  受ける形を増やすのではなく、持ち込んだ文書を崩さないための受け口
- 「生の HTML を通す」却下は変えない。`html: false` のまま、決めた形だけを見分ける

未確認: GitHub は `style` 属性を消し `align` は残す（はず）。Qiita がどちらを受けるか
は ADR-0063 の 14-0 で記法を確かめるときに見る。
