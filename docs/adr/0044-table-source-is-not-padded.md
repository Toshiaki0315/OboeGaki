# ADR-0044: 表のソースの桁揃えをやめる

- **日付**: 2026-09-04
- **状態**: 採用
- **覆す対象**: ADR-0003 決定 4「表の行から離れたときに自動で**桁を揃える**」。
  離れたときに整えること自体（決定 4 の骨）と、決定 1・2・3・5 は**そのまま**

## 背景

「本文に等幅フォント以外を使えるようにした場合の課題は何か」という問いから、
文字の幅に頼っている仕組みを数えた。**表のソースの桁揃えだけ**が該当した。

`table-format.ts` は East Asian Width で全角 2 / 半角 1 と数え、その桁数で
空白を詰めていた。これは「全角:半角 = 2:1 の等幅フォントで表示される」ことを
前提にした計算である。ところが Tauri 版では、表の行に等幅の指定が無い
（ADR-0035 決定 3 で「桁揃えの必要が無い」として本文と同じフォントにした）。
**前提はすでに崩れていた。**

## 調べたこと

同じ整形結果を 4 つのフォントで描いて縦線の位置を見た（Chromium ベースの
プレビュー・macOS）:

| フォント                        | 縦線が揃うか                        |
| ------------------------------- | ----------------------------------- |
| Hiragino Sans（今の既定の本文） | ×                                   |
| Menlo                           | ×（CJK を持たず別フォントに落ちる） |
| BIZ UDGothic                    | ○                                   |
| Osaka-Mono                      | ○                                   |

ADR-0003 の Qt での実測（Menlo 1.66 / Hiragino Sans 1.33 / BIZ UDGothic 2.00）
と同じ結論になった。**「等幅にすれば揃う」は日本語では成り立たない。**

## 決定

**空白を詰めるのをやめる。** 表を離れたときに整えるのは次の 2 つだけ:

- 区切り行を `---` / `:--` / `--:` / `:-:` に揃える（揃え記号は保つ）
- 列数の足りない行を空セルで埋める（多い行はそのまま残す）

セルは前後 1 つの空白で挟むだけにする（`| a | b |`）。

## 根拠

- 揃うかどうかは**表示に使うフォント次第**で、こちらからは決められない。
  決められないものを前提にした計算を持たない
- 普段の表は HTML のウィジェットで描かれる（ADR-0035）。生のソースが見える
  のは、キャレットが表に入っているときとソースモードのときだけ
- ソースが短くなる。桁を揃えた表は 1 セル直すだけで**行全体が変わり**、
  git の差分がまるごと 1 行になっていた
- 揃える相手（フォント）を固定する道（表の行だけ BIZ UDGothic にする）も
  あったが、設定の「等幅フォント」と別に固定のフォント名を抱えることになる。
  見た目のために設定の外に隠れた前提を作らない

## 影響

- `displayWidth` と East Asian Width の表を削除（他に使い道が無い）
- 既存のノートの表は、次にその表を離れたときに詰めた空白が落ちる。
  **ソースの意味は変わらない**（Markdown の表としては同じ）
- `src-tauri/resources/manual.md` の説明を直す
