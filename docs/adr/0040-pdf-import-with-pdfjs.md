# ADR-0040: PDF の取り込みは pdf.js で読む

- **日付**: 2026-09-04
- **状態**: 採用
- **覆す対象**: なし。参照実装 F-2（QtPdf で読む）の**道具立てだけ**を
  置き換える。整え方（core/imported.py の規則）は引き継ぐ

## 背景

参照実装は PDF を **PySide6 同梱の QtPdf** で読んでいた。「依存が増えない
のが決め手」と書かれているとおり、道具の選択は**手元にあるかどうか**で
決まっていた。

Tauri 版に QtPdf は無い。Rust 側の PDF crate（`pdf-extract` など）は
日本語の字形マップに弱く、WebView 側には Mozilla の pdf.js がある。

## 決定

1. **pdf.js（Apache-2.0）で文字だけを読む。** 動的 import にして、
   取り込むまで読み込まない（ADR-0037 と同じ）
2. **整えるのは lib/imported.ts。** PDF も PowerPoint も**同じ関数**を
   通す。2 か所に置くと片方だけ直されて、同じ資料が形式によって違う
   Markdown になる
3. **読めないことは壊れることではない。** 中身が PDF でなくても、
   暗号化されていても、空を返して呼び出し側に知らせる
4. **今回は文字だけ。** 埋め込み画像の取り出し（参照実装は pypdf）と、
   文字の無い PDF の読み取り（OCR = ADR-0027 / TASKS 4-7）は**別**。
   ここで中途半端に持ち込むと、どちらも半端に終わる

## 測ったこと

`npm run build` で pdf.js は独立したチャンクになる（本体 438KB ＋
ワーカー 2.2MB）。**主バンドルは 1,225KB**（自前のコードぶん +6KB）で、
取り込みを使うまで読み込まれない。

## 引き継ぐ判断（参照実装 core/imported.py）

- **PDF には空行が無い。** 段落の切れ目は「行が短いこと」でしか分からない
  ので、ページの中で相対的に見る（いちばん長い行の 6 割）。これが無いと
  1 ページが 1 段落に潰れる
- **和文は詰めて繋ぐ**（空白を挟むと文の途中に隙間ができる）。欧文は空白
- ページの頭が見出しらしければ `##`（資料は 1 ページ = 1 枚のことが多い）
- ページ番号だけの行は落とす。**迷ったら残す**（`2026` や `1. はじめに`）
- 取り込んだ文字は NFKC で揃える（`本⽇` のままでは「本日」で引けない）。
  ただし**全角の約物は変えない**

## 影響

- 依存が 1 つ増える（`pdfjs-dist`。Apache-2.0）
- 文字の入っていない PDF（紙を取り込んだもの）は**何も出てこない**。
  そこは 4-7（OCR）の担当で、それまでは「文字を取り出せませんでした」と出る
- 埋め込み画像は取り込まない（本文のどこに挟まっていたかは形式の側にも
  残っていない、という参照実装の注記どおり、位置は復元できない）
