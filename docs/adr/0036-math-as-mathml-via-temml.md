# ADR-0036: 数式は Temml で MathML にして画面でも書き出しでも組む

- **日付**: 2026-09-04
- **状態**: 採用
- **覆す対象**: ADR-0009（`latex2mathml` で MathML・**画面では組版しない**・
  PDF だけ LaTeX のまま）と ADR-0020（ziamath の SVG を QPixmap にして
  paintEvent で描く）の**実現手段**。見せたいもの（TeX 品質の組版・
  ソース無傷・キャレットで生の LaTeX に戻る）は全て引き継ぐ

## 背景

ADR-0009 と ADR-0020 の判断は、どちらも **Python / Qt という前提**から
出ていた。

- ADR-0009:「組版は JavaScript 実装（KaTeX / MathJax）で、Python には無い」
  → `latex2mathml`（352KB）で MathML にし、**画面では組版しない**
- ADR-0009:「Qt のリッチテキストは MathML を解さない。タグを捨てて
  `$$\frac{a}{b}$$` を `ab` にする」→ **PDF だけ LaTeX のまま出す**
- ADR-0020: 画面で組むために ziamath の SVG を QPixmap にし、0.5pt 潰し +
  先頭 1 文字拡大で高さを予約して paintEvent で描く

Tauri 版では前提が 3 つとも消えた。

1. **JavaScript 実装がそのまま使える**（アプリ本体が WebView）
2. **WebKit は MathML を自分で組む**（macOS 13+ / Safari 16.4 以降の
   MathML Core）。「タグを捨てて中身を繋ぐ」相手がいない
3. **画面に置く道具が CM6 の widget になった**。0.5pt 潰しも
   paintEvent も要らない（ADR-0035 が表で通った道）

## 決定

1. **Temml で LaTeX → MathML にする**（`temml.min.js` 168KB）。
   画面も HTML 書き出しも**同じ MathML 文字列**を使う
2. **画面では CM6 の widget で組んで見せる。** `$…$` はインライン widget、
   `$$…$$` はブロック widget。ソースには触れない（T1）
3. **キャレットが式に触れている間は生の LaTeX に戻す**（ADR-0020 と同じ
   判断。ブロックは**式全体**を戻す — 途中の行だけ生に戻ると式の断片と
   絵が同時に見えて読めない）
4. **壊れた式はそのまま生で見せる。** Temml の `throwOnError: false` は
   赤いエラー span を返すが、それを本文に埋めると「直せない何か」が出る。
   組めなかったときは LaTeX のまま置き、書いた人が直せる状態を保つ
5. **誤検出の抑えは参照実装（ADR-0009）の 3 条件をそのまま持ち込む。**
   `$` は値段にも出てくる — ここが緩いと**ふつうの文章が壊れる**

## 根拠

### なぜ KaTeX ではなく Temml か

| 案                        | 同梱するもの                                 | 書き出し |
| ------------------------- | -------------------------------------------- | -------- |
| KaTeX（HTML 出力）        | js 272KB + **フォント約 1MB** + CSS          | フォントを埋めないと崩れる |
| KaTeX（MathML 出力）      | js 272KB                                     | ○（MathML はアクセシビリティ用の副産物） |
| **Temml**                 | **js 168KB** + CSS 9KB + woff2 9KB           | ○（MathML が主目的） |

書き出した HTML は**外部リソースを参照しない**（ADR-0007 / 画像も
data URL で埋める）。KaTeX の HTML 出力を選ぶと、書き出し 1 ファイルごとに
1MB 近いフォントを埋めることになる。MathML なら**何も埋めずに**どのブラウザ
でも組める——ADR-0009 が「MathML は今のブラウザがそのまま組む」と書いた
利点は、画面が WebView になったことで**画面側にも効くようになった**。

Temml は MathML を出すために作られている（KaTeX の MathML は HTML 出力の
副産物）。同梱物も小さい。フォントは macOS の STIX Two Math が使われる。

### 測ったこと

- 変換: **100 式で 4.9ms**（1 式あたり 0.05ms。初回のロード込みで 17.5ms）。
  打鍵ごとに走らせても 16ms の予算（spec §6.6）に収まる大きさだが、
  それでも**可視範囲だけ**に限る（T6）
- 同梱: **実測で +215KB**（`npm run build` の dist/assets を before/after で
  比べた: 2,010,990 → 2,231,648 バイト。内訳は JS 約 211KB + スクリプト体の
  woff2 9.4KB）。DMG は現在 5.4MB

## 影響

- 依存が 1 つ増える（`temml` 168KB）
- **ADR-0009 の例外が消える。** 画面・HTML 書き出し・印刷（4-3）が同じ
  MathML を使う。「HTML と PDF は同じ文字列」（ADR-0007）に例外が無くなった
- ADR-0020 の描画機構（math_cache / QPixmap / 0.5pt 潰し）は**前提ごと不要**。
  CM6 の widget が高さを自分で持つ
- Temml のスクリプト体（`\mathscr`）だけは同梱フォントが要る。9KB なので
  CSS ごと同梱する
- **数式は打鍵の経路に入る。** 装飾の再計算は可視範囲だけに限り（T6）、
  同じ式を何度も組まないよう widget の `eq()` で作り直しを避ける
