# ADR-0042: ノートの鍵はパスのままにする（ULID は入れない）

- **日付**: 2026-09-04
- **状態**: 採用
- **覆す対象**: ADR-0023 の「**id で分ける**（front matter の ULID）」という
  前提。版の履歴を持つこと・置き場・間引き・保つ数と期間は**そのまま**

## 背景

ADR-0023（Qt 版）は履歴の置き場を `history/<ノートの id>/` とし、id は
front matter の ULID とした。理由は「題名（＝ファイル名）は変わる。id は
不変なので、名前を変えても履歴が途切れない」。

Tauri 版は id を持たず、**vault からの相対パス**を鍵にして（`path:仕事/会議.md`）、
名前や場所が変わるところで**鍵を付け替えて**きた（TASKS 4-12 が
「実害は出ていないので再評価する」としていた宿題）。

再評価にあたり、**今どこで付け替えているか / どこで抜けるか**を数えた。

## 調べたこと

**付け替えている場所（実装済み・テストあり）**

| 操作 | どうしているか |
| --- | --- |
| 名前を変更（題名の欄） | 旧鍵 → 新鍵へ付け替え |
| フォルダへ移動 | 同上 |
| フォルダの改名 | 中のノートぶんをまとめて付け替え |

**抜けていた場所（この ADR で塞いだ）**

| 操作 | 何が起きていたか |
| --- | --- |
| ゴミ箱へ移動 → 戻す | 戻した先に**同名の後継が居ると連番が付く**（`会議-2.md`）。鍵が変わるので、戻したノートの履歴が行方不明になっていた |

**塞げない場所（ULID でしか直らない）**

| 操作 | 何が起きるか |
| --- | --- |
| Finder や他のアプリで名前を変える・動かす | 履歴が旧い鍵の下に取り残される（30 日で消える）。**黙って失われる** |

## 決定

**パスを鍵のままにする。ULID は入れない。**

1. **鍵はファイルに付いて回る。** 名前・場所が変わる操作では必ず付け替える
   （ゴミ箱と復元も加えて、アプリの中の経路は塞いだ）
2. **外で名前を変えたときの取り残しは受け入れる。** その代わり、
   使い方ノートにそう書く（黙って失わせない）
3. 索引（`index.sqlite`）の鍵はパスのままでよい。**索引は捨ててよい
   キャッシュ**（T7）で、作り直せば必ず今のパスに揃う

## 根拠

**ULID を入れる代償が、塞げる穴に見合わない。**

| 代償 | 中身 |
| --- | --- |
| 全部のノートに front matter を書く | 外（Finder・他のアプリ・git）で作ったノートにも、**こちらの都合で書き込む**ことになる。mtime が動き、差分に出る |
| 鍵が 2 系統になる | id の無いノートはパス鍵のままなので、**どちらの鍵か**をすべての呼び出しで気にすることになる |
| 移行 | 既にある履歴のフォルダを付け替える必要がある |

得られるのは「**外で名前を変えても履歴が続く**」の 1 点だけ。この
アプリは自分が主たる編集者で、名前の変更は題名の欄から行うのが常道
（そこは既に付け替えている）。**素の `.md` を汚さない**ほうを取る。

## 覆すときの引き金

次のどれかが起きたら、この判断を見直す。

- Finder や同期アプリでの改名が**日常の操作**になった（複数の機械で
  同じ vault を触る、外のツールで一括改名する、など）
- 履歴以外にも「ノートを一意に指したい」場所が増えた（続柄・リンクの
  図・関連ノートは今のところ**題名**で足りている）
- front matter に id 以外の管理情報を持つ必要が出た（そのとき id も
  一緒に入れるほうが安い）

## 影響

- ゴミ箱→復元で履歴が続くようになった（**塞いだ穴**）
- 使い方ノートに「外で名前を変えると履歴は引き継がれません」と書いた
- ADR-0023 の履歴の設計はそのまま有効（置き場の `<id>` が `<パスの鍵>` に
  なるだけ）
