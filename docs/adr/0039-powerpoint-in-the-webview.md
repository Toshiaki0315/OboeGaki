# ADR-0039: PowerPoint は WebView 側のライブラリで読み書きする

- **日付**: 2026-09-04
- **状態**: 採用
- **覆す対象**: なし。参照実装 F-3〜F-5（`python-pptx` を使う）の
  **道具立てだけ**を置き換える。割り方・置き方・「ざっくり作って手で
  整える」という構えは引き継ぐ

## 背景

参照実装は `python-pptx` で `.pptx` を読み書きしていた。Tauri 版には
Python が無い。Rust 側にも `.pptx` を扱える成熟した crate は無い
（`docx-rs` はあるが pptx 相当は見当たらない）。

一方 `.pptx` は**XML を詰めた zip**で、WebView 側には道具が揃っている。

## 決定

1. **書き出しは `pptxgenjs`**（MIT）。ブラウザで動き、base64 で書き出せる。
   置くのは Rust（`export_write_binary`）— ファイルを書くのは Rust の仕事
   （T3）で、フロントは中身を作るだけ
2. **取り込みは `jszip` + `DOMParser`** を使って自前で読む。取り出すのは
   スライドのタイトル・段落・発表者ノートだけ。**元のレイアウトは
   復元しない**（配色・段組み・位置は形式の側に情報が残っていても
   Markdown に置く場所が無い）
3. **どちらも動的 import。** 使わない人に読み込みを払わせない
   （ADR-0037 と同じ判断）
4. 割り方（F-4）は `lib/slides.ts` に**純関数**で置き、PowerPoint を
   知らないままにする。規則をヘッドレスで固定できる
5. **解析はエディタと同じ Lezer に任せる。** パーサを 2 本にしない
   （ADR-0007 の判断）。フェンス・表・引用の細かい規則を書き直さない

## 測ったこと

`pptxgenjs` は動的 import なので独立したチャンク（372KB）になり、
**主バンドルは 1,218KB**（Mermaid のときと同じく、書き出しを使うまで
読み込まれない）。

## 引き継ぐ判断（参照実装がユーザーと決めたもの）

- `#` は表紙、`##` ごとに 1 枚、`###` 以下はスライドの中の小見出し
- 画像は**右側**。本文は左半分に寄せる（重ならないように）
- `>` の引用は**発表者ノート**（スライドには出さない）
- **書き出しは止めない。** 画像が読めなくても、そこだけ飛ばして作る。
  1 枚のリンク切れで書き出せないほうが困る
- 取り込みは**ざっくり読んで手で直す**前提。平文と第 1 階層の箇条書きは
  形式の上で見分けが付かないので、文末の記号で推測する（外れても
  目で見て直せる）

## 影響

- 依存が 2 つ増える（`pptxgenjs` / `jszip`。どちらも MIT）
- `.pptx` を書くために Rust に `export_write_binary` が増えた
  （base64 を受けてバイト列で置く）
- 取り込んだ図・表・画像は**中身だけ**が残る。見た目は戻らない
