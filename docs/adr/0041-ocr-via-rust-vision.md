# ADR-0041: 読み取り（OCR）は Rust から Vision を直に呼ぶ

- **日付**: 2026-09-04
- **状態**: 採用
- **覆す対象**: ADR-0027 の決定 2（**Swift の小さな実行ファイルを同梱する**）
  と、それに伴う配布の段取り（署名の対象が 1 つ増える・`swiftc` が無い
  環境では作られない）。読み手の選び方・切り分けの規則は引き継ぐ

## 背景

ADR-0027 が Swift の実行ファイル（63KB）を同梱したのは、**Python から
Vision を呼ぶ道具が重すぎた**ため（`pyobjc-framework-Vision` は 30MB で、
その場では結果も返らなかった）。呼び方を 2 つ比べた末の妥協で、代償として

- `.app` に同梱物が 1 つ増える
- **署名・公証の対象が 1 つ増える**
- `swiftc` が無い環境ではビルドで作られず、読み取りだけが使えない

を引き受けていた。

Rust 側の事情は違う。**objc2 の束はもう依存の中にある**（wry が
`objc2` / `objc2-app-kit` / `objc2-foundation` を使っている）。
`objc2-vision` を足せば、同じ Vision に**同じプロセスから**届く。

## 決定

**`objc2-vision` で Vision を直に呼ぶ。** 同梱物も、署名の対象も、
`swiftc` の要る作り分けも増やさない。

- 読み取りは `VNRecognizeTextRequest`。**速さより正しさ**
  （`Accurate` + 言語補正）。会議メモの金額や日付を読み違えない
- 言語は `ja-JP` → `en-US`（日本語の資料が主）
- **並びは Vision が返したまま。** 傾き補正も段組の解析もしない
  （ADR-0027 の「やらないこと」をそのまま引き継ぐ。凝ると「元と違う順で
  読める」不具合を自分で作り込む）
- **読めないことは壊れることではない。** 画像でなくても、文字が無くても、
  空を返して呼び出し側に知らせる

## 測ったこと

`fixtures/ocr/text-sample.png`（600×200、日本語 + ASCII の 2 行）を
`cargo test` から本物の Vision に通した:

| | 所要 | 結果 |
| --- | --- | --- |
| ADR-0027（Swift の実行ファイル） | 0.85 秒 | 全文正しい |
| **これ（Rust から直に）** | **0.73 秒** | **「覚書のテスト」「OboeGaki 2026」とも読めた** |

**本物の読み手を通す試験**にしてある。参照実装は「作り物のせいで試験を
すり抜けた」（LLM 側に `images` を渡していなかった）と書いており、
同じ穴を避ける。

## 引き継ぐ判断（ADR-0027 の追記）

- **切り分けはページごと。** 文書ごとに見ると、混在した PDF で絵のページが
  丸ごと落ちる
- ページの文字が **20 文字未満**なら、そのページだけ絵にして読み取る。
  **0 にしない** — 紙のページからは罫線やページ番号の誤認で数文字だけ
  取れることがあり、そこで「文字がある」と判断すると読めないまま終わる
- **読み取った結果が元より短ければ捨てる**（読み取りが外すこともある）
- **読めたページは捨てない**（読めないページのせいで全部を失わない）
- **元のファイルは触らない。** 読み取った文字で新しいノートを作るだけ

## やらないこと（ADR-0027 のまま）

- **画像をノートに貼るときの自動 OCR。** 貼るたびに待たされ、頼んでいない
  処理が走る
- **手元の LLM を読み手に選ぶ道**（ADR-0027 の決定 1）。実測で 20 倍遅く
  読み違えており、そもそも LLM 連携そのものが未実装（TASKS 4-8）。
  そちらを入れるときに一緒に考える

## 影響

- 依存が 1 つ増える（`objc2-vision`。Zlib OR Apache-2.0 OR MIT）。
  同梱物・署名の対象は**増えない**
- macOS 以外では空を返す（読み取りだけが使えない）
- PDF の埋め込み画像の取り込み（ADR-0027 の追記 2）は**まだ**。
  pdf.js からも取り出せるが、位置が復元できない点は変わらないので、
  要ると分かってから入れる
