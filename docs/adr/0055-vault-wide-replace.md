# ADR-0055: 保管フォルダ全体の検索と置換、タグの改名・統合

- 状態: 採用（実装は TASKS 12-3 / 12-4）
- 日付: 2026-09-11

## 背景

本文の中の検索（CM6 の search）はあるが、複数ノートにまたがる置換が無い。
用語の言い換え・製品名の変更は今はノートを 1 つずつ開いて直す。タグも同じで、
`#会議` と `#ミーティング` が並ぶと片づけられない（タグ一覧に改名が無い）。

## 決定

### 1. 「まとめて書き換える」の共通の土台

- Rust に `rewrite_notes(targets, edit) -> 結果` を置く。対象ノートを 1 件ずつ
  `read_note` → 純関数で書き換え → 変わったものだけ `save_atomic`。1 件の失敗
  で止めず、失敗した名前を集めて返す。書き込みは外部変更の流れに乗る
  （ADR-0053 と同じ扱い）
- **コードブロック・インラインコード・front matter の中は書き換えない**
  （既定。検索と置換の窓に「コードの中も」の印を置く）

### 2. 検索と置換（12-3）

- 検索結果（SearchHits）の下に置換の欄を足す。「n 件のノート、m 箇所を置換」
  と先に数を見せ、押してから書く。正規表現は**使わない**（書き手の道具に
  しない。素の文字列と、大小を区別するかだけ）
- 開いているノートが対象なら、先に書き切ってから（`sync.flush`）

### 3. タグの改名・統合（12-4）

- タグ一覧の右クリックに「名前を変更…」。本文の `#旧` を `#新` に。新しい
  名前が既にあるタグなら統合になる（確認を 1 回）
- 対象は索引の `tags` 表から引く。書き換えは 1 と同じ土台。**タグの字面の
  判定は `tags.rs` のスキャナと同じ規則**で行い、`#旧の続き` のような別のタグ
  を巻き込まない
- front matter の `tags:` は触らない（アプリは front matter を書かない =
  ADR-0046 の考え方）

## 根拠

| 案  | 内容                                         | 問題                                                      |
| --- | -------------------------------------------- | --------------------------------------------------------- |
| A   | ノートを開いて 1 つずつ                      | 用語の変更に付いていけない                                |
| B   | **索引で対象を引き、1 件ずつ書く共通の土台** | 大きな vault では時間がかかる（背景で走らせ、件数を出す） |
| C   | sed のような一括処理を Rust で直接           | 外部変更の流れを通らず、開いているノートと食い違う        |

B。ADR-0053 のリンク書き換えも同じ土台に乗る。

## 影響

- 検索結果の部品（SearchHits）とタグ一覧（TagSection）に UI が増える
- 置換は元に戻せない操作なので、**押す前の件数表示**と、書き換えたノートの
  版を履歴に残すことで受け止める
