# ADR-0070: 音声・動画を文字起こしして議事録のノートにする

- 状態: **採用**（2026-10-09。決めること 4 つは「決定」。実装は TASKS 第 28 群）
- 日付: 2026-10-09
- 関連: ADR-0025（ローカル LLM・送り先は 127.0.0.1 に固定）、ADR-0040（外部形式の取り込み）、
  ADR-0041（OCR は Rust から Vision を直に呼ぶ）、ADR-0051（MCP サーバの同梱）、
  ADR-0052（保管フォルダは共有されうる）、ADR-0056（やること一覧）、
  スパイク #4（[spikes/04-transcribe](../../spikes/04-transcribe/README.md)）

## 背景

「音声ファイルや動画ファイルから文字起こしをして、議事録の生成までできるか」という問い
（2026-10-09）。おぼえがきは既に、画像の字を読む（OCR = macOS の Vision）と、手元の
Ollama に要約させる道を持つ。**外へ何も出さずに**この 2 つを繋げられるかをスパイク #4 で
測った（21 分の対話の録音。macOS 26.7.1 / Apple Silicon）:

| 段 | 手段 | 時間 | 出来 |
|---|---|---|---|
| 文字起こし | macOS 26 の SpeechAnalyzer（ja_JP・この Mac の中） | 8.8 秒 | 9,108 字。用語はおおむね拾い、同音の取り違えが少し |
| 議事録 | gemma3:4b | 52 秒 | 話に無い「やること」を作った |
| 議事録 | gemma3:12b | 129 秒 | 作り話をせず、流れも細かい |

**話者は分かれない**（macOS の音声認識に話者の聞き分けは無い）。起こした文は 21 分で
約 5,000 トークン、1 時間なら 1.5 万トークン前後の見込み。

## 決定

1. **文字起こしは macOS 26 の SpeechAnalyzer（SpeechTranscriber）だけ。** スパイクで確かめた
   道だけを載せる。macOS 26 未満では「文字起こし」をメニューに出さず、手引きで案内する
   （アプリの対象は macOS 13+ のまま）。古い SFSpeechRecognizer は持たない（未検証で、長い
   録音を区切る仕組みが要る）。言語データが入っていなければ、**ダウンロードする前に確かめる**
2. **議事録のモデルは別に選べる。** 環境設定「アシスタント」に「議事録のモデル」を足す。既定は
   gemma3:12b が入っていればそれ、無ければ普段のモデル。普段の要約は速い 4b のまま、議事録は
   作り話をしにくい大きいモデルで
3. **長い録音は区切って 2 段でまとめる。** `[mm:ss]` の区切りで約 15 分ずつに分け、各区切りから
   要点を抜き出し、最後に 1 つの議事録にまとめる。長さに上限を作らず、記憶も食わない。
   区切りをまたぐ話が少し薄まるのは受け入れる
4. **元の音声・動画は添付に写す。** `attachments/` に元のファイルを写し、ノートからリンクする
   （後で聞き直せる）。保管フォルダが膨らむので、**写す前に大きさを見せて確かめる**

### 形（決定から導いたもの）

- 入口は「ファイル」→「インポート」→「音声・動画（文字起こし）…」。取り込んだノートは
  他の取り込みと同じく**選んでいるフォルダ**に作る（18-2）
- 1 枚のノートにする:

  ```markdown
  # 議事録 2026-10-09 ラズパイで試す工場共通言語OPC_UA

  [元の録音（21 分）](attachments/….m4a)

  ## 要旨
  ## 話されたこと      ← 各項目の頭に [mm:ss]
  ## 決まったこと      ← 無ければ「なし」
  ## やること          ← `- [ ] `（やること一覧に載る。ADR-0056）。無ければ「なし」
  ## 用語

  :::details 文字起こし（音声認識。話者は分かれていません）
  [00:00] …
  :::
  ```

- **作り話を抑える。** 頼み方に「文字起こしに書かれていないことは書かない」と書き、後処理で
  崩れを直す（`\[ ]` → `[ ]`、`- [ ] なし` → `なし`）。それでも外れるので、**ざっくり作って
  手で直す**前提を手引きに書く（PDF・PowerPoint の取り込みと同じ構え）
- Ollama が動いていなければ、**文字起こしだけのノート**を作る（議事録は後から頼める）
- **Swift の小さな実行ファイルを同梱する。** SpeechAnalyzer は Swift からしか呼べない（Vision の
  ように Rust から直に呼べない = ADR-0041 の構えが使えない）。`oboegaki-transcribe`（音声・動画の
  パス → `[mm:ss] 文` の行を標準出力）を組んで `Contents/MacOS/` に置き、Rust が子プロセスで
  呼ぶ。MCP サーバ（ADR-0051）と同じ置き方で、署名・公証の対象が 1 つ増える
- 動画は AVFoundation がそのまま音声を読む（ffmpeg は要らない）
- 時間がかかる（1 時間の録音で数分の見込み・**未実測**）ので、進み具合を出し、止められること

## 根拠

| 案 | 内容 | 問題 |
|---|---|---|
| A | **macOS の音声認識 + 手元の Ollama** | macOS 26 が要る。話者は分かれない |
| B | whisper.cpp（Whisper のモデルを手元で） | モデル 1〜3GB の同梱か別の取得。配布が 5.4MB から大きく膨らむ |
| C | 外の文字起こし・要約のサービス | 音声を外へ出す（ADR-0025 の「外へ出さない」に反する）。鍵も要る |

A を採る。速さ（21 分を 9 秒）と出来がスパイクで足りた。精度が足りない声が出たら B を、
言語データの取り込み口として別の ADR で検討する。

## 守れないもの・手引きに書くこと

- 話者の聞き分けはしない（できない）
- 固有名詞・同音の取り違えは残る。議事録は作り話をすることがある（とくに小さいモデル）
- 添付に写した音声は施錠しても隠れない（ADR-0062 の添付と同じ）。共有フォルダでは同期が重くなる
- 文字起こしも議事録も**この Mac の中だけ**で行い、音声は外へ出さない
