# ADR-0052: 共有フォルダに置いた保管フォルダを複数人で使う

- 状態: 採用（実装は TASKS 第 11 群）
- 日付: 2026-09-11

## 背景

「複数のユーザーから参照・編集できるか」という問い（2026-09-11）。同時に
同じノートを編集する（CRDT と中継サーバ）までは要らず、**別々のノートを
書き、たまに同じものを触る**小さなチームなら、保管フォルダを共有フォルダ
（iCloud Drive・Google Drive・Dropbox・SMB など）に置き、各人が自分の Mac で
おぼえがきを動かす形で足りる。

外部変更の仕組み（spec §7.5）は既にこの形を受け止められる。他人の保存は
外部変更として届き、未編集なら静かに読み直し、編集中なら競合の 3 択になる
（ADR-0050 の NFC 揃え、中身比較も効く）。壊れるのは**保管フォルダの中に
置いている「自分の Mac だけのもの」**だ。

## 決定

### 1. 「保管フォルダは共有してよい。索引とロックは各 Mac のもの」

保管フォルダ（`.md`・`attachments/`・`templates/`・`.trash/`・履歴）は共有の
対象。**索引と二重起動ロックは共有しない** — 各 Mac の App Support
（`app_data_dir`）に、保管フォルダのパスを鍵にした置き場を作って持つ。

```
~/Library/Application Support/app.oboegaki.desktop/
  vaults/<保管フォルダのパスのハッシュ>/
    index.sqlite            # 索引（T7: 捨ててよい）
    instance-oboegaki.lock  # 二重起動ロック（flock）
```

- 索引の SQLite は同期ソフトで運ぶと壊れる（WAL と -shm を別々に運ぶ）。
  キャッシュ（T7）なので各 Mac が自分で育てればよい。`IndexDb::open` の
  引き数を「管理フォルダ」から「索引の置き場」に変え、置き場は 1 箇所
  （`index_dir(root)`）で決める
- ロックは flock なので同期経由では効かず、実害は無いが、同期ソフトが
  ファイルの取り合いで揉める。ロックも索引と同じ置き場へ
- 既存の `.OboeGaki/index.sqlite` は開くときに一度だけ消す（捨ててよい）。
  `instance-oboegaki.lock` も同じ

### 2. 履歴は共有する。書き手の名前を鍵に混ぜる

`.OboeGaki/history/` は作り直せない（ADR-0023）ので共有の対象。鍵は
`path:<相対パス>` で、2 人が同じノートの版を同じ瞬間に残すと衝突し得る。
版のファイル名に**書き手**（ホスト名。`scutil --get ComputerName` 相当）を
混ぜ、履歴の窓では書き手を添えて出す。「誰がいつ変えたか」がここで見える。

### 3. 競合コピーの名前に書き手を入れる

「両方残す」で作る `名前 (競合 YYYY-MM-DD).md` を
`名前 (競合 YYYY-MM-DD ホスト名).md` にする。同期ソフト自身も競合コピー
（"conflicted copy" など）を作るので、アプリ側のものが誰のかを見分けられる
ようにする。同期ソフトの競合コピーは**アプリからは触らない**（一覧には出る。
中身を見て手で片づける）。

### 4. Google Drive は「ミラーリング」でだけ支える（2026-09-12 追記）

Google Drive for desktop には 2 つのモードがあり、**ミラーリング**
（ローカルに実体を置く）でだけ支える。**ストリーミング**
（`~/Library/CloudStorage/GoogleDrive-<アカウント>/` に実体のない置き石を
並べる）は非推奨:

- 保管フォルダを開くと、索引を作るために全ノートを読む。置き石のままでは
  そこで全件のダウンロードが走る（5,000 ノート 2.2 秒の実測はローカル前提）
- 変更の検出は `notify`（FSEvents）に頼っている（`watcher.rs`）。
  FileProvider 越しに同期デーモンが書いたとき FSEvents が飛ぶ保証が無く、
  **他人の保存が届かない**恐れがある

Drive 特有の縁が 2 つ:

- Drive は同じ名前のファイルを許すので、競合すると手元に `名前 (1).md` が
  降りてくる。一覧には別のノートとして並ぶ — 決定 3 のとおり**アプリからは
  触らない**（中を見て手で片づける）
- 履歴（`.OboeGaki/history/`）は共有対象なので、小さなファイルが大量に
  Drive に載る。ファイル数が増えたときの同期の遅さは 11-4 で見る

**仕組みから導いた見立てで、実機では未確認**（2026-09-12 時点。開発機に
Google Drive が入っていない）。11-4 で確かめる。

### 5. 同期の遅れへの備え

- 監視は「今ここに在るか」で分類しているので、同期ソフトの一時ファイルや
  遅れて届く rename にも既に耐える。追加の手当は要らない
- 自分の保存の直後に届く同期ソフトの触り直しは、中身比較（3-26）が捨てる
- **同時に同じノートを触ることは支援しない。** 後から保存した人に競合の
  3 択が出る。それで足りない規模になったら、CRDT（Yjs + CodeMirror 6）を
  別の ADR で検討する

### 実装の記録（2026-10-02。TASKS 11-1）

- 置き場は `Vault::local_dir()`。`Vault::new(root)` が
  `~/Library/Application Support/<identifier>/vaults/<path_key(root)>/` に決める
  （鍵は退避と同じ `path_key`）。**Tauri の `app_data_dir` には頼らない** —
  MCP サーバ（別のプロセス）も同じ置き場を計算し、アプリと同じ索引とロックを見る。
  identifier が tauri.conf.json とずれないことはテストが見張る
- 鍵はパスの字面から作る（正規化しない）。アプリと MCP サーバで字面が違う
  （シンボリックリンク越しなど）と置き場が分かれるが、索引が 2 つになるだけで壊れない
- ホームが分からなければ旧の置き場（`.OboeGaki/`）に落とす。そのときは古い索引を消さない
- テストでは本物の App Support に書かない（`#[cfg(test)]` の既定は一時フォルダの
  管理フォルダの中）

### 実装の記録（2026-10-02。TASKS 11-2）

- 版の名前は `<日時>@<書き手>.md`。書き手は `scutil --get ComputerName`（1 回だけ
  問い合わせて覚える）を `author_label` で整えたもの（`/` `:` 制御文字は `-`、NFC、
  40 字まで）。読めなければ書き手なしの古い形で残す。`@` の無い版は書き手不明
- **間引き（60 分）と、同じ秒の版を避けて秒を進めるのは、同じ書き手の版だけを
  相手にする。** 他の人の直しで自分の版が間引かれず、他の Mac の時計の進みに
  自分の版の時刻が引きずられない。**中身の重複は誰の版とでも見る**（同期で届いた
  同じ本文を二重に残さない）
- 版は 2 台で同じ秒になりうる。MCP の `at`（時刻で名指す）は同じ秒の版が複数あると
  並びの先頭を返す。画面は版のパスで引くので取り違えない

### 実装の記録（2026-10-02。TASKS 11-3）

- 競合コピーは `名前 (競合 YYYY-MM-DD 書き手).md`。書き手は 11-2 と同じ `this_mac()`。
  読めなければ今までの `名前 (競合 YYYY-MM-DD).md`。同じ人の同じ日のものは連番で逃がす

## 根拠

| 案  | 内容                                             | 問題                                                                            |
| --- | ------------------------------------------------ | ------------------------------------------------------------------------------- |
| A   | **共有フォルダ + 各 Mac の索引・ロック**         | 同時編集は支援しない（3 択で受ける）                                            |
| B   | 1 台をサーバにして MCP（HTTP）で複数人が読み書き | 人が直接書く UI が無い。認証が要る（ADR-0051 の延長として別に検討）             |
| C   | CRDT と中継サーバで同時編集                      | 数週間。T1 の上に同期層を重ね、保存・履歴・外部変更を見直す。製品の性格が変わる |

A を採る。変更が小さく、既存の競合の仕組みが払い戻される。C が本当に要る
かは、A を使って「同じノートを同時に触ることがどれだけあるか」を見てから。

## 影響

- `IndexDb::open(&vault.managed_dir())` を呼ぶ 25 箇所が `index_dir(root)`
  に変わる。テストは一時フォルダを置き場に渡す形にする
- 索引を App Support に移すと、保管フォルダを別の Mac に丸ごとコピーした
  ときに索引が付いてこない。初回は背景の全同期（2.2 秒 / 5,000 ノート）で
  育つので許容
- CLAUDE.md T7 の文言「`.OboeGaki/index.sqlite` は捨ててよいキャッシュ」を
  「索引は捨ててよいキャッシュ（置き場は App Support）」に直す
- 履歴の版のファイル名に書き手が入るので、`history.rs` の読み書きと窓の
  表示が変わる。古い版（書き手なし）は「不明」として読む
