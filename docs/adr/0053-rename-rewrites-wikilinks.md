# ADR-0053: ノートの改名で `[[リンク]]` を書き換える

- 状態: 採用（実装は TASKS 12-1）
- 日付: 2026-09-11

## 背景

見出しとファイル名を両方向で揃えるようにした（ADR-0005 追記、3-30）ので、
改名は「意識してやる操作」から「見出しを直したら起きること」になった。
一方、`[[題名]]` は名前で解決する（ADR-0011）ため、改名すると他のノートから
のリンクは静かに切れる。`references.rs` が見ているのは添付の名前だけで、
ノート間のリンクは誰も追っていない。

## 決定

- 改名（題名欄・見出しの追従・右クリック）の後、**索引の `links` 表**で旧題名を
  `target` に持つノートを引き、その本文の `[[旧題名]]` / `[[旧題名|表示]]` を
  新題名に書き換える。判定は `wikilink::normalize`（NFC・空白のゆれ）で行い、
  書き込みは `save_atomic`。1 ノート 1 回の書き込み
- 書き換えは本文の編集なので、開いているノートには外部変更の流れで届く
  （未編集なら静かに読み直し。編集中なら競合の 3 択 — 3-26 の中身比較は
  「同じ」ではないので出る。改名の直後に別のノートを打っている人にだけ起きる
  稀なケースとして受ける）
- コードブロック・インラインコードの中は書き換えない（例として書いた
  `[[…]]` を壊さない）。`links` 表の作り方と同じ除外規則
- 書き換えた件数はステータスに出す（「3 件のノートのリンクを直しました」）。
  失敗したノートは名前を添えて知らせ、改名そのものは戻さない（ファイル名の
  真実は本文にある = ADR-0005）
- 履歴（`.OboeGaki/history/`）は書き換えたノートの側にも残す（ふつうの保存
  と同じ経路）

## 根拠

| 案  | 内容                                     | 問題                                               |
| --- | ---------------------------------------- | -------------------------------------------------- |
| A   | 何もしない（今）                         | 3-30 で改名が増え、リンク切れが静かに増える        |
| B   | **改名時に指しているノートを書き換える** | 他人のノートに手を入れる。件数を知らせて透明にする |
| C   | 解決側で旧名の別名表を持つ               | 真実が 2 つになる（T1）。Finder 改名には効かない   |

B。索引の `links` 表が既にあり、追加の走査が要らない。

## 影響

- Rust: `note_rename` / `folder_rename`（中のノートは題名が変わらないので
  対象外）の後段に `rewrite_links(old_title, new_title)` を足す。純 Rust で
  テストできる（本文の書き換えは純関数、書き込みは Vault）
- 「両方残す」の競合コピーや、ゴミ箱の中は対象外
