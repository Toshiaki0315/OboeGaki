# ADR-0046: 環境設定「PowerPoint」タブを、覚書の作りにどう載せるか

- **日付**: 2026-09-06
- **状態**: 採用（2026-09-06。1〜4 を決定。実装は TASKS 第 8 群）
- **決めること**: [OboegakiPptxSettingsSpec.md](../OboegakiPptxSettingsSpec.md)
  （設定仕様 v1.0）を、既にある書き出し（ADR-0039 / ADR-0045）の上にどう載せるか

## 背景

設定仕様 v1.0 が持ち込まれた。よく書けているが、**そのままは載らない**。
仕様は自分を「出力仕様（`oboegaki-pptx-export-spec.md`）の L1 層」と位置づけ、
その ID を前提に話を進めるが、**その出力仕様はこのリポジトリに無い**。

参照されていて**覚書に無い**もの: グリッド（`G-xx`）・タイプランプ（`T-xx`）・
情報密度（`SH-xx`）・溢れとコントラストの判定（`L-01` / `L-04`）・
**文字幅テーブル**（`MEAS-01`）・レイアウトの型（`C-xx`）・Frame IR・lint。

今の書き出しは ADR-0039 の「ざっくり作って手で整える」構えで、
`slides.ts`（割り方）と `pptx.ts`（描き方）だけでできている。座標は枠ごとの
直値で、**溢れるかどうかを測る仕組みは無い**。

## 調べたこと（実測 2026-09-06）

1. `applyThemeParts` は出来上がった `theme1.xml` の `<a:clrScheme>` と
   `<a:fontScheme>` を**丸ごと**差し替える（ADR-0045 案 A）
2. `pptx.theme`（`headFontFace` / `bodyFontFace`）は pptxgenjs の
   `makeXmlTheme` が **`fontScheme` に書く**（ソースで確認）
3. 1 と 2 から、**テンプレートを選んでいる間、ノートの `slide-font` は
   効かない**（テンプレートが後から上書きする）。仕様の優先順位
   （SC-03 > SC-02 > SC-01）と逆で、今ある取りこぼし
4. 図形の色はテーマ参照（`accent1` など）で書いてある。だから
   **PowerPoint 側でテーマを替えると追従する**（5-6 で意図して入れた性質）

## 決定

### 1. 設定仕様だけを、覚書の作りに読み替える（出力仕様は持ち込まない）

**8-1〜8-4・8-8 を実装し、8-5〜8-7（情報密度・プレビュー・警告）は
エンジンの話として棚上げする。**

理由: この仕様がいちばん強く言っているのは「**設定は逃げ道であって、
既定値の代わりではない**」（1.2）。逃げ道を先に作っても既定値の質は
上がらない。一方、用紙サイズと配色は**今の出力の質を直接上げる**。

棚上げしたものに手を付けるときは、**幅テーブル（MEAS-01）から**入る。
測れないうちは溢れ警告もプレビューも作れない（見せかけだけになる）。

### 2. テンプレートは「配色プリセットの取り込み」にする

テンプレート（`.pptx`）を選んだ時点で、その `clrScheme` と `fontScheme` を
**設定の値として読み込む**。以後はテンプレートとの縁を切り、設定として
編集できる（仕様の `presetId` / `[テーマを読み込み]` = ST-05 と同じ形）。

- **却下: テンプレートが常に勝つ** — 「選んだのに設定が効かない」が起きる
- **却下: 設定が常に勝つ** — 「テンプレートを選んだのに反映されない」が起きる

これで調べ 3 の取りこぼし（テンプレートが front matter を上書きする）も
消える。**仕様の付録 B は「マスター適用は v2」と書いているが、覚書はもう
入れてある**ので、そこは仕様側が古い（この ADR で上書きする）。

### 3. 色は「テーマ参照」と「6 桁の具体色」の 2 つを持てる型にする

内部の色を `{ ref: "accent1" } | { hex: "1E2761" }` の形で持つ。既定は
**テーマに従う**（今と同じ）。設定でユーザーが色を選んだ項目だけ具体色に
落ちる。

CFG-17（`#` なし 6 桁に正規化）は**具体色を持つときの形**の規則として
守る。あれは pptxgenjs に `#` 付きや 8 桁を渡すと**ファイルが壊れる**ため
の事故防止であり、テーマ参照を禁じる条文ではない。

理由: 「何も触らなければテーマに従い、触った色だけ固定される」が、
触った人の意図に一番忠実。プレビュー（8-6）を作るときは、テーマ参照を
その時点の実色に解決して描けばよい。

### 4. 文書ごとの上書きは front matter のまま（サイドカーを作らない）

`slide-font` / `slide-mono` / `slide-accent`（5-5）を **SC-06 の
「ユーザーが書いたもの」として読む**。アプリからは書き込まない（SC-04 の
精神）。**優先順位は SC-02 > SC-01** に直す（決定 2 で自然に解決する）。

**却下: サイドカー（DB / `.OboeGaki/`）に持つ。** 覚書は「`.md` がすべて、
それ以外は捨ててよい」（T1 / T7）で組んである。文書ごとの設定をサイドカーに
置くと、

- `.md` を Finder で別の場所へ写すと**設定だけ置き去りになる**
- 保管フォルダを引っ越すと消える。索引と違い**作り直せない**

つまり**捨ててよくないものが `.md` の外に増える**。仕様 SC-04 の狙い
（Markdown を勝手に汚さない）は「**アプリから書き込まない**」で満たす。

将来、UI から文書ごとに設定させたくなったら、そのときだけ front matter へ
**ユーザーの明示操作として**書き込む。黙って生やさない。

## 結果

- TASKS 第 8 群の 8-1〜8-4・8-8 を実装する。8-5〜8-7 は幅テーブルが
  入るまで着手しない
- 設定仕様の付録 B（マスター適用は v2）は、この ADR で上書きされた
- 出力仕様（`oboegaki-pptx-export-spec.md`）を後で持ち込むときは、
  この ADR の決定 1 を見直すところから始める
